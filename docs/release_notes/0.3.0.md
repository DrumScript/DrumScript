## Highlights

**MIDI-only export.** If all you need is a MIDI file for your DAW, you can now
skip the sheet music and the transcription JSON:

```bash
drumscript "drum_loop.wav" --midi-only
```

```python
import drumscript as ds

result = ds.transcribe("drum_loop.wav", midi_only=True)
print(result["midi_path"])
```

The transcription itself is unchanged. Onsets are still detected and hits still
classified, because a MIDI file of drum notes cannot be produced without that
work. Only the PDF and JSON writes are suppressed, so there is still one
transcription pipeline rather than two.

**A transcription regression harness.** `tests/regression/` replaces the manual
before-and-after routine used when tuning classification. One file,
`test_regression.py`, is both a pytest module and a command-line tool with `run`,
`compare` and `verify` subcommands. Point it at your own audio via a gitignored
`songs.json`; the committed `songs.example.json` documents the schema.

**Wider benchmark coverage.** ENST-Drums and MDB-Drums adapters join the existing
IDMT-SMT-Drums V2 support, with diagnostic scripts for per-onset stage
attribution and threshold sweeps.

## New Features

* `midi_only` on `transcribe()` and `score_builder.build_score()`, and a matching
  `--midi-only` CLI flag. `build_score()` is the single place that decides which
  files get written; both the CLI and the Python API pass the flag straight to it.
* Transcription regression harness at `tests/regression/`, with
  `songs.example.json` documenting the config schema and its own `README.md`.
* `scripts/check_harness.sh`, a smoke test for the harness itself.
* ENST-Drums and MDB-Drums benchmark adapters, registered in `benchmarks/run.py`.
* Diagnostic modes in the IDMT and ENST research scripts: per-onset pipeline-stage
  attribution, feature capture, and a threshold grid sweep scored by precision,
  recall and F-measure.
* Troubleshooting page covering known dependency warnings and install errors.
* Issue forms for bug reports, feature requests and submitted results.
* PyPI version and monthly download badges on the README and docs homepage.

## Fixes & Improvements

* When Demucs
  was unavailable or failed, `drumscript song.flac --full-song` tidied up by
  removing the directory it had been told to write into, which defaults to
  wherever you ran the command from. Cleanup now removes only the folder Demucs
  itself created. Reported in
  [#356](https://github.com/DrumScript/DrumScript/issues/356).
  **If you use `--full-song` on v0.2.1 or earlier, please upgrade.**
* Demucs is now invoked through the running Python interpreter rather than the
  `demucs` command on `PATH`. Installing DrumScript as a tool
  (`uv tool install drumscript`) links DrumScript's own entry point but not
  Demucs's, so stem separation failed even though Demucs was installed and
  importable. A genuinely missing Demucs now says so plainly instead of printing
  a traceback.
* MIDI export no longer fails when the output filename has no parent directory.
  `os.path.dirname()` returns an empty string for a bare name such as
  `my_drums.mid`, and `os.makedirs("")` raised `FileNotFoundError`. Carried over
  from [#348](https://github.com/DrumScript/DrumScript/pull/348).
* `tests/unit/test_cli_args.py` now tests the real `build_parser()` from
  `main.py` rather than a parallel copy, so the tests cannot drift from the CLI.
* Expanded docstrings in `score_builder.py` for the time signature default and
  the non-zero constraint on `quantization_subdivision`.

## Upgrading

```bash
pip install --upgrade drumscript
```

No breaking changes. `transcribe()` behaves exactly as before unless you pass
`midi_only=True`, in which case the returned mapping carries `midi_path` alone
and `pdf_path` and `json_path` are `None`.

Python 3.9 through 3.12 are supported, unchanged from v0.2.1. Python 3.13 is
still blocked, tracked in [#303](https://github.com/DrumScript/DrumScript/issues/303).
